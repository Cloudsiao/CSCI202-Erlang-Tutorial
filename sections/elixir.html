Introduction to Elixir

Elixir is a functional programming language created by José Valim. Although Elixir is a separate language from Erlang, both run on the same BEAM virtual machine and use the Erlang/OTP ecosystem.

Elixir was designed around three main goals: compatibility, productivity, and extensibility. It builds upon Erlang's existing runtime while introducing additional language abstractions and developer tools.

1. Compatibility with Erlang

Erlang and Elixir execute on BEAM and can use the same Erlang/OTP libraries. Both languages support lightweight processes, asynchronous message passing, and supervision mechanisms.

Elixir can call Erlang functions directly without requiring a separate runtime.

Example: Calling an Erlang Function

Erlang

lists:reverse([1,2,3]).

Result:

[3,2,1]

Elixir

:lists.reverse([1,2,3])

Result:

[3,2,1]

Explanation: Both examples call the same Erlang lists:reverse function. Erlang uses module:function syntax, while Elixir uses :module.function syntax.

Key Takeaway: Elixir does not replace Erlang's runtime. Both languages share BEAM processes, message passing, and OTP mechanisms.

2. Productivity Through Macros

Elixir uses a relatively small language core, implementing many convenient programming constructs as macros instead of hardcoding them into the compiler.

A macro generates or transforms code during compilation. This allows developers to create new programming abstractions without modifying the compiler.

Example 1: Using the unless Macro

The unless macro executes a block of code when its condition is false or nil. 

temperature = 25

unless temperature > 30 do
    IO.puts("Not too hot")
end

Output:

Not too hot

The example is equivalent to: 

if not (temperature > 30) do
    IO.puts("Not too hot")
end

The unless construct is implemented as a macro using existing Elixir language mechanisms.

Example 2: Creating a Custom Macro

Developers can also define their own macros. The following example creates a custom conditional construct called my_unless. 

defmodule MyMacros do
    defmacro my_unless(condition, do: block) do
        quote do
            if not unquote(condition) do
                unquote(block)
            end
        end
    end
end

require MyMacros

temperature = 25

MyMacros.my_unless temperature > 30 do
    IO.puts("Not too hot")
end

Output:

Not too hot

How Does the Macro Work?

  1. defmacro defines a custom macro.
  2. quote constructs the code to be generated.
  3. unquote inserts the supplied expressions into the generated code.
  4. During compilation, the macro expands into a conditional expression.

Key Takeaway: Elixir's macro system allows developers to define reusable language constructs without changing the compiler. Fundamental special forms such as case cannot be overridden.

3. Extensibility Through Protocols

Elixir's third design goal is extensibility. Protocols allow developers to extend existing operations to additional data types without modifying the original library.

A protocol is not simply a built-in function. It defines a set of functions that implementations must provide for supported data types.

Understanding Protocols

Concept Meaning
Protocol Defines a common set of operations.
Implementation Specifies how those operations work for a particular data type.
Function Call Invokes the appropriate behavior for the data.

Example 1: Enumerable Protocol

The Enum module provides functions for processing collections. Collections implementing the Enumerable protocol can use these operations.

Using a List

Enum.map([1, 2, 3], fn x -> x * 2 end)

Result:

[2, 4, 6]

Using a Range

Enum.map(1..3, fn x -> x * 2 end)

Result:

[2, 4, 6]

Both lists and ranges implement the Enumerable protocol. Therefore, Enum.map can operate on either type using the same interface.

Example 2: Custom Enumerable Type

Developers can implement Enumerable for their own data structures. The following NumberBox structure stores a list of items. 

defmodule NumberBox do
    defstruct items: []
end

defimpl Enumerable, for: NumberBox do

    def count(box) do
        {:ok, length(box.items)}
    end

    def member?(box, value) do
        {:ok, value in box.items}
    end

    def slice(_box) do
        {:error, __MODULE__}
    end

    def reduce(box, acc, fun) do
        Enumerable.List.reduce(
            box.items, acc, fun
        )
    end
end

box = struct(NumberBox, items: [1, 2, 3])

Enum.map(box, fn x -> x * 2 end)

Result:

[2, 4, 6]

Explanation: NumberBox is a custom structure. By implementing Enumerable, NumberBox can use the existing Enum.map function.

The Enum module does not need to be modified to support the new data type.

Example 3: String.Chars Protocol

Protocols are not limited to collections. Another example is String.Chars, which defines how different data types can be converted into strings.

Integer

to_string(123)

Result:

"123"

Float

to_string(3.14)

Result:

"3.14"

Atom

to_string(:hello)

Result:

"hello"

Although integers, floats, and atoms are different types, each implements String.Chars. Therefore, the same function can convert them into strings.

Example 4: Custom String Conversion

Suppose a developer creates a Person structure. By default, this structure does not have a String.Chars implementation. 

defmodule Person do
    defstruct name: ""
end

We can implement String.Chars for this custom structure: 

defimpl String.Chars, for: Person do
    def to_string(person) do
        person.name
    end
end

Now the existing to_string function can handle Person: 

person = struct(Person, name: "John")

to_string(person)

Result:

"John"

Explanation: String.Chars defines the conversion behavior, while the Person implementation specifies how that conversion works. The existing to_string function uses the appropriate implementation.

Key Takeaway: Protocols let developers extend existing operations to custom data types without modifying the original library.

4. Summary: Erlang vs. Elixir

Erlang and Elixir share the same BEAM runtime and Erlang/OTP ecosystem. However, Elixir introduces additional language abstractions and tools that emphasize productivity and extensibility.

Feature Erlang Elixir
Runtime BEAM BEAM
Concurrency BEAM processes BEAM processes
Fault Tolerance OTP supervision OTP supervision
Macros Preprocessor macros AST-based macros
Extensibility Modules and behaviours Modules, macros, and protocols

Overall Conclusion: Elixir is a separate programming language built on Erlang's established runtime. Its main contributions are additional abstractions, development tools, and extensible APIs rather than a different concurrency model.
