Features Inherited from Prolog

Erlang was originally developed using Prolog, and several Prolog features were retained in Erlang's syntax and programming conventions. These include atoms, variable naming conventions, dynamic typing, recursion, clause-based definitions, and list notation.

Example: Head-Tail List Notation

Both Prolog and Erlang use [H|T] notation. H represents the first element (head), while T represents the remaining elements (tail). The underscore (_) means the remaining elements are ignored in these examples.

Prolog - Predicate

first([H|_], H).

Query:

?- first([10,20,30], X).

Result:

X = 10

Erlang - Function

first([H|_]) -> H.

Function call:

first([10,20,30]).

Result:

10

Key Difference: Prolog uses unification to bind X to 10, while Erlang matches the list and returns the value of H directly.

Unification vs. Pattern Matching

Prolog uses two-way unification, which attempts to make two terms identical by binding variables on either side. Erlang instead uses one-way pattern matching, where a left-hand pattern is matched against a right-hand value.

Backtracking vs. Function Clause Evaluation

Prolog uses backtracking to explore alternative solutions. Erlang checks function clauses in order and executes the first matching clause.

Key Difference: Prolog can undo variable bindings and revisit alternative clauses through backtracking. Erlang selects the first matching function clause without searching for additional solutions.

From Prolog to Erlang: WAM, JAM, and BEAM

Erlang's implementation evolved from a Prolog-based interpreter into a virtual machine designed for concurrent and fault-tolerant applications. The Warren Abstract Machine (WAM) influenced the design of Joe's Abstract Machine (JAM), which later gave way to BEAM.

WAM - Warren Abstract Machine

An abstract machine designed for Prolog. It supports efficient unification and backtracking during logical inference.

1986 - Erlang's Prolog Interpreter

The first implementation of Erlang was written in Prolog. It allowed developers to experiment with language features, but was too slow for practical applications.

1989 - JAM (Joe's Abstract Machine)

JAM borrowed implementation ideas from WAM but eliminated backtracking while adding support for concurrent processes, message passing, and failure detection.

BEAM - Bogdan's Erlang Abstract Machine

BEAM provided a more efficient execution system for Erlang. It was subsequently improved and became the runtime foundation of Erlang/OTP.

Key Takeaway: Erlang retained elements of Prolog's syntax and implementation techniques, but evolved toward functional programming, concurrency, message passing, and fault tolerance.
