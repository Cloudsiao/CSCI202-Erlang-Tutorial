1. Introduction to Akka and Scala

Scala is a statically typed programming language combining functional and object-oriented programming.

Akka is a framework for developing concurrent and distributed applications using Scala and Java. It provides actor-based programming while running on the Java Virtual Machine (JVM).

Similar to Erlang, Akka follows the actor model, where actors maintain private state and communicate through asynchronous message passing.

2. Actor-Based Concurrency

Both Erlang and Akka support actor-based concurrency. Each actor has its own logical state and mailbox, and handles incoming messages sequentially. Different actors can execute concurrently.

In Erlang, actors are implemented as lightweight BEAM processes with isolated memory. Akka actors are managed by the framework and scheduled using JVM threads.

Example: Sending a Message

Erlang

Worker = spawn(fun() ->
    receive
        hello ->
            io:format("Hello from Erlang!~n")
    end
end),

Worker ! hello.

Output:

Hello from Erlang!

The spawn function creates a lightweight process. The ! operator sends a message, while receive handles incoming messages.

Scala with Akka Typed

import akka.actor.typed.ActorSystem
import akka.actor.typed.scaladsl.Behaviors

val worker = Behaviors.receiveMessage[String] {
    case "hello" =>
        println("Hello from Akka!")
        Behaviors.same

    case _ =>
        Behaviors.same
}

val system = ActorSystem(worker, "WorkerSystem")

system ! "hello"

Output:

Hello from Akka!

ActorSystem starts an actor system with the specified guardian behavior. The ! operator sends an asynchronous message. The actor processes the message and returns Behaviors.same to continue using its current behavior.

Key Difference: Erlang provides lightweight processes directly through BEAM, whereas Akka provides actor-based concurrency as a JVM framework.

3. Fault Tolerance and Supervision

Erlang/OTP and Akka both support fault tolerance through supervision. Instead of requiring every actor to recover from unexpected errors independently, supervision provides strategies for handling failures.

How Does Supervision Differ?

Erlang/OTP: Dedicated supervisor processes manage child processes and apply configured restart strategies.

Akka: Actors are organized in parent-child hierarchies. Supervision is integrated into actor behaviors and the framework's actor lifecycle.

Erlang/OTP Restart Strategies

  • one_for_one: Restart only the failed child.
  • one_for_all: Restart all children when one fails.
  • rest_for_one: Restart the failed child and children started after it.

Akka Typed Supervision Strategies

  • Stop: Terminate the failed actor.
  • Restart: Reinitialize the failed actor's behavior.
  • Resume: Continue processing messages without restarting the behavior.

Akka Typed stops an actor by default when an unexpected exception occurs without a configured supervision strategy. Akka Classic generally restarts actors for ordinary unhandled exceptions.

5. Summary: Erlang vs. Akka/Scala

Feature Erlang Akka/Scala
Execution Runtime BEAM JVM
Actor Implementation BEAM processes Akka framework actors
Communication Asynchronous messages Asynchronous messages
Supervision Dedicated supervisors Actor behaviors and hierarchy
Default Failure Handling Depends on process and OTP setup Typed: stop; Classic: usually restart

Overall Conclusion: Erlang and Akka both apply actor-based concurrency and supervision to build fault-tolerant applications. Erlang implements these features in the BEAM runtime and OTP libraries, while Akka brings actor programming into the Scala and Java JVM ecosystem.
