1. Introduction to Pony

Pony is a statically typed, actor-oriented programming language that compiles to native machine code. Like Erlang, it supports concurrency through independent actors and asynchronous message passing.

However, Erlang is dynamically typed and runs on BEAM, while Pony uses a static type system with reference capabilities to enforce safe access to mutable and immutable objects.

Example: Pony Actors

actor Main
    new create(env: Env) =>
        greet(env)

    be greet(env: Env) =>
        env.out.print("Hello from Pony!")

Output:

Hello from Pony!

The actor keyword defines an actor. The be keyword defines an asynchronous behaviour. Calling a behaviour schedules a message for the actor to process.

2. Reference Capabilities

A reference capability specifies how a reference may access, modify, or share an object. Pony's compiler checks these capabilities to enforce concurrency-safety guarantees.

Every reference has a type and a reference capability. The type describes the object, while the capability determines the permitted access through that reference.

The Six Reference Capabilities

Capability Purpose Directly Sendable?
iso Isolated mutable access Yes
val Deeply immutable access Yes
ref Mutable local access No
trn Mutable, convertible toward val No
box Read-only access No
tag Identity-only access Yes

The discussion focuses on iso, val, and ref because they demonstrate Pony's approach to ownership transfer, immutable sharing, and mutable local references.

Isolated (iso)

An iso reference provides isolated access to mutable data. Ownership can be safely transferred to another actor because the sender gives up usable access to the transferred object.

Value (val)

A val reference provides deeply immutable access. Multiple actors may safely share the same data because no actor can modify it.

Reference (ref)

A ref reference permits mutable access and multiple local aliases. However, it cannot be sent directly between actors because it does not provide the guarantees required for safe cross-actor sharing.

4. Memory Management and Concurrency Safety

Erlang relies on process isolation and immutable terms. Each Erlang process normally has its own heap, and ordinary message data is copied between processes on the same node.

Pony instead uses compiler-enforced reference capabilities to control access to objects. An iso object can be transferred between actors, while val objects can be shared without copying the underlying data.

Erlang also has sharing optimizations: reference-counted binaries and certain literal data can be shared between processes on the same node. Therefore, not every Erlang message requires copying all underlying data.

Comparing Data Transfer

Scenario Erlang Pony
Mutable objects Immutable language terms Allowed under capability rules
Ordinary messages Generally copy terms Can pass safe references
Mutable ownership transfer No equivalent for ordinary terms iso
Immutable sharing Special sharing optimizations val
Concurrency safety Process isolation and immutability Compiler-checked capabilities

5. Summary: Erlang vs. Pony

Both Erlang and Pony provide actor-based concurrency with asynchronous message passing. However, they use different approaches to memory safety.

Erlang emphasizes isolated processes, immutable terms, and fault recovery through OTP. Pony emphasizes compiler-enforced reference capabilities that permit controlled mutation, safe ownership transfer, and immutable sharing.

Key Takeaway: Erlang generally avoids shared mutable state by isolating processes. Pony allows carefully controlled object access through reference capabilities checked at compile time.
